# PRD · 《猜猜我》MVP v3

**项目**：guess-me（独立项目，与本工作区其他内容无关）
**日期**：2026-09-29
**状态**：冻结（MVP v3）

## 1. 一句话产品

系统从内置题库随机抽 5 题，两人各自选出"自己的答案"并互猜，通过链接完成，全程无服务器、无账号。

## 2. 目标用户与场景

- 任意两个有手机浏览器的人（A 和 B），主要在微信内互相发送链接。

## 3. 核心流程（固定，不得更改）

A 抽 5 题选自己的答案 → A 生成链接 → B 打开猜 A 的答案 → B 抽另外 5 题选自己的答案 → B 生成返回链接 → A 打开猜 B 的答案 → 本地计算双方结果。

## 4. 功能需求

| ID | 需求 |
|----|------|
| F1 | 题库固定内置（当前 81 题 / 9 类），随机抽 5 题、每局 5 个不同类别 |
| F2 | A 的答案与 B 的答案、B 的猜测均通过 URL Fragment（Base64URL 编码的 ID 协议）传递 |
| F3 | B 的 5 题自动排除 A 用过的题目 ID |
| F4 | A 的最终猜测只在 A 本机内存计算，不写回 URL |
| F5 | 分享优先 navigator.share，不支持则复制链接 |
| F6 | 非法/损坏/错版本/未知题目 ID/重复题/答案越界/超长 Fragment → 统一错误页文案，且内部有可区分的 ERR_* 码，不得抛未捕获 JS 错误 |
| F7 | 刷新回到当前环节重做（内存+hash 为准，不落盘） |

## 5. 威胁模型（产品决策 2026-09-29，用户选择方案 1）

- 接受：**拿到链接的人可以解码看到答案**。防顺手翻看，不防有心人解码。
- 页面与 README 如实声明这一点；禁止"绝对没有任何数据泄露可能"类表述。
- 不做口令、加密、服务器（若将来要"猜前不可见"= 产品形态变更，需重新立项）。

## 6. 非目标（明确不做）

自由文本、多题型、AI、聊天、图片、排行榜、登录、账号、房间、后端、数据库、云存储、Analytics、广告、防重放签名、密码学方案。新想法只进 Future Ideas。

## 7. 成功标准

两个真人（含微信内置浏览器）用同一份静态页面走完 §3 全流程并看到正确得分；A→B 链接 ≤300 字符、B→A ≤500 字符。
